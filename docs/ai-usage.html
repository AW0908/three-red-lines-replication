RESEARCH PROCESS

AI runs and tokens

An audit of the recorded workflow: who ran the tasks, how they were reviewed, and where token records are incomplete.

A run is a completion entry with a tier or model and a priority in the run log of the agent scripts. Start notes are not runs. Tokens are included only when a log contains a “tokens used” line; each log is attributed to the most recent matching Codex run. Logs of earlier runs may have been overwritten, so token counts are lower bounds. Missing tokens are not zero; no missing values are imputed or extrapolated.

Runs by provider

Known tokens are a partial sum, with the observed run coverage shown below each bar. A value of 0 means that no token line was recorded for these runs, not that none were used.

Claude models as logged

Model families are shown only where the run tier records them. Dates and current provider settings are never used to infer a model.

Task-card status

“Status not readable” means the front matter could not be parsed; no status is inferred from the report or output.

Review rounds

One round groups the verdicts that follow a worker run. ESCALATE takes precedence over REWORK, which takes precedence over PASS. The denominator counts rounds with logged verdicts.

PI events

These are logged events. An override is separate from ordinary acceptance. Approve authorizes execution; accept delivers the result; return sends the card back to PLAN.

Start notes and completion entries

A start note is paired with the first later completion for the same task, role and provider on the same calendar day, before the next matching start note. Unpaired notes are excluded from the run count.

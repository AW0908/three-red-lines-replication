RESEARCH PROCESS

AI runs and tokens

An audit of the recorded workflow: who ran the tasks, how they were reviewed, and where token records are incomplete.

A run is a completion entry with a tier or model and priority in the agent-script run log. Start notes are not runs. Tokens are included only when a log contains a “tokens used” line; the latest available log is assigned to the latest matching Codex run. Earlier logs may have been overwritten. Missing tokens are not zero; no missing values are imputed or extrapolated.

Claude models as logged

Model families are shown only where the run tier records them. Dates and current provider settings are never used to infer a model.

Task-card status

“Status not readable” means the front matter could not be parsed; no status is inferred from the report or output.

Review rounds

One round groups verdicts following a worker run. ESCALATE takes precedence over REWORK, then PASS. The denominator counts rounds with logged verdicts.

PI decisions

These are logged events. An override is separate from ordinary acceptance; approve authorizes execution, and return sends the card back to PLAN.

Start notes and completion entries

A start note is paired with the first later completion for the same task, role and provider on the same calendar day, before the next matching start note. Unpaired notes are excluded from the run count.
